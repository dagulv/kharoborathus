# Step 2: Enrich Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn each accepted raw post into a `posts` row with a summary, tags and discovery, off peak, retrying failures up to 10 times.

**Architecture:** A new `internal/core/service/enrich` package holds `Enrich(ctx, l, rawPostID)`, its prompt, the Jev tagging and the background job. Step 1's sink sends accepted ids to a channel read by 5 enrich workers. A job ticking through DeepSeek's schedule picks up the rest. Stores live in `internal/adapter/postgres`.

**Tech Stack:** Go 1.27, pgx v5, DeepSeek through `port.LLM`, Jev through `port.Classifier`.

**Spec:** `docs/superpowers/specs/2026-11-08-enrich-design.md`

## Global Constraints

- `001_init.sql` is edited in place.
- No new dependencies.
- The user's Go style applies: `any`, guard clauses, default-then-override, `fmt.Errorf("err <what>: %w", err)` at leaves, terse comments only.
- Values: summary 300 chars, excerpt 280 chars, tag proposals 5, keys in prompt 300, article 20,000 runes for DeepSeek and 60,000 for Jev, Jev threshold 0.8, 50 tags per Jev request, job 20 per one-minute tick, job gap 5 minutes, 5 workers, max retries 10.
- Trusted source: `enabled AND status = 'active'`.
- DB tests use `dbtest.New(t)`, which skips without `TEST_POSTGRES_CONN`.
- One commit per task. Never push.

## Review Focus

1. **A post enriched twice.** The live path and the job race. The second post insert is a no-op, and `Discover` does not run twice. `TestEnrichExistingPost` in Task 3.
2. **A raw post with `retry_count = 10`.** Never picked or enriched again. `TestListUnenrichedRetryCap` in Task 2 and `TestEnrichSkipsExhausted` in Task 3.
3. **Shutdown mid-enrich.** Not counted as an attempt. `TestEnrichCancelled` in Task 3.
4. **A proposal key that is an alias of an active tag.** Adds nothing. `TestSaveProposals` in Task 2.
5. **`lang` such as `sv-SE`, `EN` or empty.** Becomes `sv`, `en` or empty. `TestNormalizeLang` in Task 1.

### Task 2: Stores for enrich

**Files:**
- Modify: `internal/adapter/postgres/raw_post.go`, `raw_post_test.go`
- Create: `internal/adapter/postgres/post.go`, `post_test.go`, `tag.go`, `tag_test.go`

**Interfaces:**
- Produces, on `RawPostStore`:
  - `GetRawPost(ctx, id string) (domain.RawPost, error)`
  - `ListUnenriched(ctx context.Context, limit int, minAge time.Duration, maxRetries int) ([]string, error)`: ids that are `accepted`, or `failed` with `retry_count < maxRetries`, with no post by `url`, and `created_at < now() - minAge`. Ordered by `retry_count, created_at`.
  - `FailEnrich(ctx, id string) error`: sets `status = 'failed'` and `retry_count = retry_count + 1`.
- Produces, `PostStore` with `NewPostStore(db)`:
  - `PostExists(ctx, url string) (bool, error)`
  - `InsertPost(ctx context.Context, tx pgx.Tx, p domain.Post) (domain.Post, bool, error)`: `ON CONFLICT (url) DO NOTHING`. The bool is false when the post already existed.
  - `Trusted(ctx context.Context, sourceID string) (bool, error)`
- Produces, `TagStore` with `NewTagStore(db)`:
  - `type Tag struct { Key string; Terms []string }` in package `domain`, extending `domain.Tag` if that fits better.
  - `TagKeys(ctx) ([]string, error)`: every key, any status.
  - `ActiveTags(ctx context.Context, lang string) ([]domain.Tag, error)`: `enabled` and `active` tags, with their terms in `lang`, ordered by key.
  - `SaveProposals(ctx context.Context, tx pgx.Tx, lang string, proposals []Proposal) ([]string, error)`, where `type Proposal struct { Key string \`json:"key"\`; Term string \`json:"term"\` }`. For each proposal:
    1. Map the key through `tag_aliases`. Keys arrive already normalized: Task 3 runs `discovery.TagKey` on them.
    3. Insert into `tags` as `status = 'proposed'` with `ON CONFLICT DO NOTHING`.
    4. If the tag's status is `proposed`, insert `(key, lang, term)` into `tag_terms` when `lang` and `term` are non-empty, and add the key to the result.

    Returns deduplicated keys.

- [ ] **Step 1: Write failing DB tests**
  - `TestListUnenriched`: accepted, failed with count 3, failed with count 10, an already-posted url, one newer than 5 minutes, and a rejected one. Assert the ids and their order.
  - `TestListUnenrichedRetryCap`: a failed row with count 10 is excluded.
  - `TestFailEnrich`: count goes up by one each call, and status becomes `failed`.
  - `TestInsertPost`: a second insert with the same url returns `false`.
  - `TestTrusted`: enabled and active is true. Disabled or proposed is false.
  - `TestActiveTags`: only enabled and active tags, terms only for the given lang.
  - `TestSaveProposals`:
    - a new key becomes proposed, gets its term and is returned,
    - an existing proposed key gets the term and is returned,
    - an active key returns nothing and adds no term,
    - an alias of an active tag returns nothing,
    - an empty lang adds no term.
- [ ] **Step 2: Run, expect failure.** Undefined methods.
