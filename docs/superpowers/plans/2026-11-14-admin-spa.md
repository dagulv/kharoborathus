# Admin SPA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the admin out of the SvelteKit web app into a static shadcn-svelte SPA on bunny.net. The Go app serves every admin read and write and owns login.

**Architecture:** The Go app gets cookie sessions, CORS and JSON admin routes under `/admin/`, backed by new postgres store methods that port the SQL in `frontend/src/routes/admin/admin.remote.ts`. A new SvelteKit project in `admin/` builds with `adapter-static` and SSR off, and loads data in `+page.ts` load functions through one fetch client. CI uploads the build to a Bunny Storage zone.

**Tech Stack:** Go 1.27, net/http ServeMux, pgx v5, golang.org/x/crypto/scrypt. SvelteKit 3 next, Svelte 5 runes, Tailwind 4, shadcn-svelte 1.x, valibot, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-14-admin-spa-design.md`

## Global Constraints

- JSON keys are camelCase. Errors are plain text with a status, written by `http.Error`.
- Session cookie: name `session`, HttpOnly, Secure, SameSite Strict, Path `/admin`, Max-Age 30 days, no Domain attribute.
- Token: 32 random bytes, base64url without padding. `sessions.token_hash` holds `sha256(token string)`.
- Password hash format: `<hex 16-byte salt>:<hex 64-byte key>`, scrypt N 16384, r 8, p 1.
- `ADMIN_ORIGINS` env, comma separated, default `http://localhost:5173`. Prod: `https://admin.kharoborathus.dagulv.me`.
- Writes (`POST`, `PATCH`) require `Content-Type: application/json`, else 415.
- Page size 50 for posts and logs. Logs have no total and use `LIMIT 51` to set `hasNext`.
- Brave search budget shown on the overview: 322.
- Log types: `deepseek, jev, brave, rss, page, trim, ingest, robots, homepage, wordpress`. Levels: `INFO, WARN, ERROR`.
- Validation limits: tag key 1 to 40 chars, tag filter at most 200, search at most 500 trimmed, metadata key 1 to 100 trimmed, metadata value at most 500 trimmed, rate an integer of at least 1, lang `""`, `sv` or `en`, adapter `rss` or `page`.
- SPA: `PUBLIC_API_URL` defaults to `http://localhost:3001`. Prod build uses `https://api.kharoborathus.dagulv.me`.
- Go style per the user's CLAUDE.md: `any`, wrapped errors (`fmt.Errorf("err <what>: %w", err)`) at leaves, guard clauses, default-then-override assignment. Comments only for non-obvious intent.
- Never use npx. Use `pnpm dlx`.
- Commit after each task. Never push.
- Go DB tests need `TEST_POSTGRES_CONN`, for example `TEST_POSTGRES_CONN=postgresql://postgres:<pw>@localhost:5432/postgres?sslmode=disable` with the dev compose db running. Without it they skip, so run them with it set.

## Review Focus

1. **A disallowed origin.** A request or preflight from `https://evil.example` gets no `Access-Control-Allow-*` headers, so the browser blocks it. Test in Task 3.
2. **A logged-out cookie.** After `POST /admin/logout`, the same cookie gets 401 on `GET /admin/session`. Test in Task 3.
3. **Odd search input.** A search of `"`, `-` or `!!!` returns 200 with a list, never 500. `websearch_to_tsquery` accepts any text. Test in Task 5.
4. **A tag key with a space or slash.** `PATCH /admin/tags/a%2Fb` and `PATCH /admin/tags/a%20b` reach the right tag. The SPA encodes keys with `encodeURIComponent`. Test in Task 6.
5. **A listing URL only held by a deleted source.** Creating a source with it succeeds. Only live sources block a duplicate. Test in Task 4.

**Files:**

**Interfaces:**
- Consumes: Task 1 `password.Verify` and `password.Hash`. Task 2 `UserStore` and `SessionStore` methods.
- Produces:
  - `auth.SessionCookie = "session"`, `auth.SessionDays = 30`.
  - `auth.RequireSession(s Sessions, l *slog.Logger, next http.Handler) http.Handler`, now reading the `session` cookie. The bearer header is gone.
  - `auth.RequireJSON(next http.Handler) http.Handler`: 415 for `POST` or `PATCH` without a `Content-Type` whose media type is `application/json`.
  - `auth.Routes(public, protected *http.ServeMux, users Users, sessions LoginSessions, l *slog.Logger)` registers `POST /admin/login` on `public`, and `POST /admin/logout` and `GET /admin/session` on `protected`. `Users` and `LoginSessions` are small interfaces over the Task 2 methods.
  - `cors.Allow(origins []string, next http.Handler) http.Handler`.
  - `config.Environment.AdminOrigins []string` with tags `env:"ADMIN_ORIGINS" envSeparator:"," envDefault:"http://localhost:5173"`.

Login behavior: decode `{email, password}` and trim the email. A bad body gives 400. An unknown email still runs `password.Verify` against a dummy hash made once at startup with `password.Hash`, so a miss takes as long as a wrong password. A wrong password or unknown email gives 401. Success creates the session and sets the cookie per Global Constraints, then answers 204. Logout deletes the session for the request's cookie, sets the cookie with `MaxAge: -1` and answers 204. Session answers 204, since `RequireSession` already ran.

CORS behavior: for a request whose `Origin` is in the list, set `Access-Control-Allow-Origin: <origin>`, `Access-Control-Allow-Credentials: true` and `Vary: Origin`. An `OPTIONS` request from an allowed origin also gets `Access-Control-Allow-Methods: GET, POST, PATCH`, `Access-Control-Allow-Headers: Content-Type` and `Access-Control-Max-Age: 600`, and answers 204 without calling `next`. An `OPTIONS` request from any other origin answers 204 with no CORS headers. Other requests always reach `next`.

Wiring in `cmd/main.go`:

```go
protected := http.NewServeMux()
source.Routes(protected, &sourceStore, syncs, l.WithGroup("source"), calls)
admin.Routes(protected, ...) // Task 4 onward

adminMux := http.NewServeMux()
auth.Routes(adminMux, protected, &userStore, &sessionStore, l.WithGroup("auth"))
adminMux.Handle("/admin/", auth.RequireSession(&sessionStore, l.WithGroup("auth"), protected))
mux.Handle("/admin/", cors.Allow(env.AdminOrigins, auth.RequireJSON(adminMux)))
```

Update the comment above the admin mux: the port is public, so every admin route except login sits behind the session cookie.

**Interfaces:**
- Consumes: the Task 3 routes `POST /admin/login`, `POST /admin/logout`, `GET /admin/session`.
- Produces:
  - `api<T>(path: string, opts?: { method?: 'GET' | 'POST' | 'PATCH'; body?: unknown; query?: Record<string, string | number | undefined>; fetch?: typeof fetch }): Promise<T>`. It always uses `credentials: 'include'`. For `POST` and `PATCH` it always sends `Content-Type: application/json` with `JSON.stringify(body ?? {})`. Undefined and empty query values are dropped. A 204 resolves to `undefined`. A JSON response is parsed. A non-ok response throws `ApiError`.
  - `class ApiError extends Error { status: number }`, with `message` set to the response text.
  - `types.ts`: `Stats`, `Source`, `SourceCheck`, `ListingCandidate`, `PostSummary`, `Post`, `PostPage`, `Tag`, `TagProposal`, `TagAlias`, `TagOverview`, `LogSummary`, `Log`, `LogPage`, and `LOG_TYPES` from `frontend/src/lib/types.ts`. Shapes match the Go JSON from Tasks 4 to 7. Date fields are ISO `string`s. Log `id` is a `number`.
  - `format.ts`: `fmtDateTime(iso: string)` with `sv-SE` short date and time, `fmtDate(iso: string)` with short date, `fmtDateTimeSeconds(iso: string)` with short date and medium time, and `withParams(params: URLSearchParams, changes: Record<string, string | undefined>): string`, ported from today's pages.
