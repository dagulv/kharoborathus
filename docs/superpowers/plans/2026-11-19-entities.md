# Entities Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entities of any kind that posts link to, gate and prioritize discovery, and get weekly depth searches when focused.

**Architecture:**
- **Schema.** Migration `003_entities.sql` adds the entity tables, swaps the unique query constraint for a partial index, and backfills entities from `normalized_entity`.
- **Enrich.** Enrich extracts entities in its DeepSeek call, then resolves, links and promotes them in its transaction.
- **Discover.** `Discover` receives the post's linked entities. It gates event queries on them and creates depth queries for focused ones.
- **Search.** The search worker adds the depth freshness, filter question and daily cap, and a priority order for the catch-up.

**Tech Stack:** Go, pgx v5, tern migrations, Postgres, Brave Search, DeepSeek, Jev, SvelteKit SPA with shadcn-svelte.

**Spec:** `docs/superpowers/specs/2026-11-19-entities-design.md`

## Global Constraints

- **Order.** Runs after `docs/superpowers/plans/2026-11-19-categories.md` Tasks 1 to 7. It uses `migrations.MigrateTo`, `dbtest.Empty`, `ClassifiableTags` and the two-stage Jev from there.
- **Language.** Task 3 stores terms under `raw_posts.lang`. Merge the fix for wrong `en-US` langs on Swedish posts before Task 3.
- **Prompt.** `userPrompt` is now `userPrompt(lang, title string, authors, keys, qualityKeys, categoryKeys []string, markdown string)`. Task 3 appends `entityKeys` at the end.
- **Admin.** Tasks 8 and 9 need the admin SPA plan executed and categories Task 8 done. Stop after Task 7 if `internal/core/service/admin` does not exist.
- **Migrations.** `001_init.sql` and `002_categories.sql` are never edited. The new file is `internal/migrations/003_entities.sql`. No `{{` in SQL.
- **Entity rules.**
  - Kinds are exactly `company`, `organization`, `technology`, `product`, `strategy` and `concept`.
  - Keys are normalized with `discovery.TagKey`.
  - At most 8 entities per post.
  - At most 300 entity keys in the prompt.
  - `name` is at most 200 characters.
- **Strength.** Posts linked in the last 30 days, from any source, computed on read.
- **Promotion.** At least 3 linked posts from sources with `enabled` and `status = 'active'`, on at least 2 distinct domains, within 30 days.
- **Depth.**
  - `action = 'depth'` with a 7-day window and freshness `pm`.
  - At most 50 depth searches per day, inside the 322 daily cap.
  - Depth queries come last in the catch-up order.
- **Never.**
  - An untrusted post never creates an entity.
  - A disabled entity is never linked, searched or public.
  - The system never sets `focus`.
  - A proposed, unfocused entity never creates a query.
- **Go style** per `~/.claude/CLAUDE.md`: `any`, wrapped errors in leaf calls, guard clauses, default assignment.
- **DB tests** need `TEST_POSTGRES_CONN`. Without it they skip, so run them with it set.

## Review Focus

1. Two extracted entities in one post resolve to the same entity, for example `Volvo Cars` and `Volvo Car Corporation` through an alias. Expect one link and no primary key error. Task 2.
2. Short terms ground loosely: `AI` is inside `fair`. Expect terms of 3 runes or fewer to need a whole-word match, while longer terms keep substring matching so Swedish inflections like `solid state-batterier` still ground. Task 2.
3. DeepSeek returns `kind` as `"Technology"` or `"person"`. Expect the first lowercased and kept, and the second dropped. Task 2.
4. A depth query whose text equals an existing event query's text. Expect both to exist, with no conflict. Task 5.
5. You turn focus on twice within a week. Expect one depth query. Task 8.

### Task 2: Entity resolution, linking and promotion

**Files:**
- Create: `internal/core/domain/entity.go`

**Interfaces:**
- Produces in `domain`:

  - `Entity{Key, Name, Kind, Status string; Enabled, Focus bool; Terms map[string][]string; Tags []string; Strength int; CreatedAt time.Time}`, with JSON camelCase. `Terms` maps lang to terms.
  - `LinkedEntity{Key, Status string; Focus bool; Names []string; Aliases []string; Term string}`.

    - `Term` is the extracted term that grounded it in this post.

It runs the spec's resolution and linking steps 1 to 6, then promotion, and returns the linked entities in extraction order, deduplicated by key, with their status after promotion.

      - **Kind:** lowercased, and dropped unless it is in `EntityKinds`.
      - **Limits:** names are cut at 200 characters, and only the first 8 extracted entities are read.
      - **Locks:** `pg_advisory_xact_lock(hashtext('entity/' || key))` in sorted key order, before any read of an entity.
      - **Promotion:** the spec's rule, for linked `proposed` entities.

**Interfaces:**
- Produces:
  - `const DepthAction = "depth"`, `depthFreshness = "pm"` and `dailyDepthBudget = 50`.
  - `QueueDepth(ctx context.Context, tx pgx.Tx, entity, postID, query string) (id string, created bool, err error)`. It locks `(entity, "depth")`, returns `created = false` when `recentQuery(entity, DepthAction, 7)` finds one, and otherwise inserts with no conflict clause and links the post.
  - `Query` gains `Freshness string`. Brave sends it, or `pw` when it is empty.
  - The `searchStore` interface and `Store` gain `DepthSearchesLastDay(ctx) (int, error)`. It counts depth queries with `searched_at` in the last day and a non-null result.
- Behavior:
  - `Discover`: for a trusted post, each linked entity with `Focus` calls `QueueDepth` with its `Term`. New ids go to `Found.Queries`.
  - `search()`: for a depth item, it holds back when `DepthSearchesLastDay >= 50`, logged with reason `daily depth budget`, and searches with `Freshness: "pm"`.
  - `ResultFilter.Keep`: when `action == DepthAction` it uses `depthQuestion`:
    - Instructions: `Does this search result substantially cover the given entity?`
    - True: `Its main subject is this entity, as a news article, press release, company page or report from any site.`
    - False: `It mentions the entity only in passing, is a listing, search, tag or category page, a stock quote or a profile page, or its text does not show the entity.`
